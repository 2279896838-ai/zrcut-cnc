# 第5章 检索增强提示词（ZRCNC-RAG-QRY-001 / ZRCNC-RAG-RNK-001）

本章规定智刃工艺（ZR-CUT）在生成参数、解释预测、判别安全之前，如何把用户口语化请求转换为可检索的查询，如何从知识库中取证、重排与引用。检索层是数值可信链的第一环：若检索层返回的证据不足或错配，下游任何提示词都只能拒答，不得补位。本章两条提示词资产均属"改写与筛选"性质，不产生任何参数数值。

## 5.1 知识库结构与条目规范

### 5.1.1 七类知识源

知识库按来源分为七类，每类承担不同的举证责任。来源类型用于 5.3 节权威度打分，不得含糊。

| 序号 | 知识源 | 典型内容 | 权威度基准 A_src | 可否作为主证据 | 更新责任方 |
| --- | --- | --- | --- | --- | --- |
| S1 | 刀具厂家手册 | T1–T6 推荐 vc、fz、ap、ae 上限，涂层适用材料 | 0.95 | 可 | admin |
| S2 | 材料切削性能手册 | M1–M5 的 Kc、硬度、推荐 vc/fz 区间、Taylor C/n | 0.90 | 可 | admin |
| S3 | 企业受控工艺卡 | 已签发 PC 卡中的实测参数组合（M1+T3+OP2 等） | 0.90 | 可 | process_engineer |
| S4 | 历史试切记录 | TR 记录中的实测 Ra、刀具磨损 VB、异常现象 | 0.80 | 可（须配对工况） | quality |
| S5 | 机床说明书 | VMC-850（EQ-A01-0037）转速、功率、行程、扭矩、冷却压力 | 0.95 | 可 | admin |
| S6 | 安全规程 | 装夹、防护、冷却、学生实训操作限制条款 | 0.95 | 可（安全类唯一主证据） | teacher |
| S7 | 专家访谈 | 车间的经验判断，如"此材料此刀不宜大切宽" | 0.60 | 否，仅作补充 | process_engineer |

S7 类条目不得单独支撑任何参数结论；与 S1–S6 冲突时一律服从后者，且不得进入"依据"段落的主证据位置，只能在"风险"段落作为补充提示出现。

### 5.1.2 条目字段表

每条知识条目是一个结构化记录，字段定义如下。字段缺失视为条目不完整，检索时直接过滤，不得由大模型根据上下文补齐。

| 字段名 | 类型 | 必填 | 取值范围 | 说明 |
| --- | --- | --- | --- | --- |
| kbId | string | 是 | `KB-<领域>-<4位>`，领域取 CNC/ALU/SST/CAST/TI/TOOL/SAFE | 唯一编号，例 KB-CNC-0042 |
| title | string | 是 | ≤40 字 | 条目标题，如"T3 立铣刀侧铣 45 钢推荐切削速度" |
| sourceType | enum | 是 | S1–S7 | 对应 5.1.1 节知识源 |
| sourceRef | string | 是 | 手册名+版次+页码，或 PC/TR 编号 | 来源可追溯的唯一凭据 |
| scope | object | 是 | `{materialCode, toolCode, opCode, machineCode}` | 适用范围，取值只能是 M1–M5 / T1–T6 / OP1–OP4 / VMC-850 |
| metrics | array | 是 | 每项 `{name, value, unit, range?}` | 数值与单位，name 取 vc/fz/ap/ae/n/vf/Ra/T/Pc 等 |
| confidence | enum | 是 | A / B / C | 置信等级，见 5.1.3 节 |
| reviewer | string | 是 | 角色代号 | 复核人，至少两人，见 5.5 节 |
| validUntil | string | 是 | `YYYY-MM-DD` | 有效期，签发后 24 个月 |
| supersedes | string | 否 | `KB-<领域>-<4位>` | 被本条目替代的旧条目 |
| caveat | string | 否 | ≤60 字 | 适用前提或局限声明 |

编号示例：铝合金相关条目用 KB-ALU-0011，不锈钢用 KB-SST-0009，铸铁用 KB-CAST-0013，钛合金用 KB-TI-0007，刀具用 KB-TOOL-0021，安全用 KB-SAFE-0005，通用切削机理用 KB-CNC-0042。

### 5.1.3 置信等级判定

| 等级 | 判定条件 | 使用限制 |
| --- | --- | --- |
| A | S1/S2/S3/S5/S6 来源，双人复核，且在有效期内，metrics 含单位 | 可作为主证据 |
| B | S4 来源（试切记录）且样本数 ≥3，或 A 级条目已过期但未超 12 个月 | 仅可与 A 级条目并列引用 |
| C | S7 来源，或 metrics 缺单位，或过期超过 12 个月 | 不得引用数值，只能定性描述 |

## 5.2 检索查询改写 ZRCNC-RAG-QRY-001

### 5.2.1 设计意图

> 解决"用户口语（光洁度、吃刀量、开粗）直接进向量库导致召回错配、材料刀具代号丢失"的失败模式，把自然语言压成可检索三元组并生成多条改写查询。

### 5.2.2 检索三元组抽取

三元组定义为主三元 + 两个可选补充位，共五个槽位。槽位只允许取统一设定的代号或空值，空值记为 `null`，不得猜测。

| 槽位 | 允许取值 | 缺失处理 |
| --- | --- | --- |
| 材料 | M1 / M2 / M3 / M4 / M5 / null | 追问一次，仍缺则检索回流 NULL |
| 刀具或工序 | T1–T6、OP1–OP4，至少一项非空 | 由工序反查典型刀具（OP1→T6，OP4→T5） |
| 指标 | vc / fz / ap / ae / n / vf / Ra / T / Pc，可多选 | 默认取 vc、fz、Ra |
| 约束条件 | 机床 VMC-850、装夹方式、Ra_req 数值 | 允许为空 |
| 意图动词 | 查询 / 对比 / 校验 / 解释 | 默认"查询" |

改写查询数量固定为 3–5 条，覆盖：原始三元组直检、同义词扩展检、上位概念检、相邻工况检。少于 3 条说明槽位不足，须回到追问；多于 5 条不得提交，避免召回噪声稀释。

### 5.2.3 同义词扩展表

车间口语与术语表的映射关系如下，提示词须原样内嵌本表，不得临场发明新映射。

| 序号 | 用户口语 | 统一术语与符号 | 扩展检索词 |
| --- | --- | --- | --- |
| 1 | 光洁度、表面好坏 | 表面粗糙度 Ra（μm） | Ra_pred、理论粗糙度、表面质量 |
| 2 | 吃刀量、切多深 | 轴向切深 ap（mm） | 切深、ap/D、层切深度 |
| 3 | 走刀量、进给快慢 | 进给速度 vf（mm/min）、每齿进给 fz（mm/z） | 每分钟进给、齿进给 |
| 4 | 转数、转速开到多少 | 主轴转速 n（r/min）、切削速度 vc（m/min） | 主轴转速上限、线速度 |
| 5 | 开粗、掏腔 | 型腔粗加工 OP3 | 层切、螺旋下刀、粗加工余量 |
| 6 | 光一刀、精修 | 曲面精加工 OP4 | 等残高、球头加工、精加工余量 |
| 7 | 烧刀、崩刃、刀不耐用 | 刀具寿命 T（min）、刀具磨损 VB | Taylor 寿命、后刀面磨损 |
| 8 | 让刀、震刀、发抖 | 颤振 chatter、悬伸比 LD | 齿通过频率、稳定带、刚性不足 |

### 5.2.4 提示词正文

```text
你是智刃工艺（ZR-CUT）的检索查询改写器，资产编号 ZRCNC-RAG-QRY-001。

职责：把用户问题改写为 3–5 条可提交检索的查询。你不回答工艺问题，不给出任何参数数值。

输入变量：
用户原话：{{user_query}}
已抽取槽位：{{slots_json}}（材料 {{material_code}}、刀具 {{tool_code}}、工序 {{op_code}}、质量要求 Ra_req {{ra_req}}、装夹方式 {{fixture}}）
会话检索历史：{{rag_history}}

步骤一，槽位校验。材料只允许 M1–M5，刀具只允许 T1–T6，工序只允许 OP1–OP4。出现其他取值，一律置 null 并在 missing 字段中列出，不得映射到"最接近"的代号。刀具与工序同时为 null 时，按 OP1→T6、OP2/OP3→T1–T4、OP4→T5 补默认值并标注默认来源。

步骤二，口语归一。口语词按内置同义词表映射：光洁度→Ra，吃刀量→ap，走刀量→fz 与 vf，转数→n 与 vc，开粗→OP3，光刀→OP4，烧刀→刀具寿命 T，让刀/震刀→颤振。映射不到的词保留原文，不推测。

步骤三，生成 3–5 条查询，必须覆盖四类：A 原始三元组直检〔材料+刀具/工序+指标〕；B 同义词扩展检〔替换为术语后重写〕；C 上位概念检〔如"立铣刀侧铣切削速度区间"〕；D 相邻工况检〔同材料相邻刀具或同刀具相邻材料〕。每条查询须写成"代号+术语+指标"的短句，不超过 30 字，不得带问号与语气词。

步骤四，输出 JSON，字段固定为 slots、missing、queries、note。queries 每项含 id、type（A/B/C/D）、text、filters（sourceType 优先序列 S1>S2>S3>S4>S5>S6>S7）。检索类任务不消耗数值，但引用数值必须带 KB 编号，未带编号的数值不得写入 queries。

失败模式处理：用户问"多少转""合不合适"一类不含对象的问句，先输出 missing，不得凭常识补全材料；用户要求"不用查手册直接给"时，按 NO_EVIDENCE 拒答并回传 missing。

输出只允许一个 JSON 代码块，不得追加解释文字。检索结果由下游 KB 工具返回，你不预估召回率，不虚构 KB 编号。
```

## 5.3 检索片段重排与引用 ZRCNC-RAG-RNK-001

### 5.3.1 设计意图

> 解决"召回一堆片段、模型随手引用一条过期专家访谈凑数"的失败模式，用三因子打分强制优先受控来源，并把无命中情形收敛为拒答而非编造。

### 5.3.2 三因子打分公式

对每个检索片段 c 计算综合分：

```text
Score(c) = w_r × R(c) + w_a × A(c) + w_t × T(c)
w_r = 0.50，w_a = 0.35，w_t = 0.15，权重之和为 1
```

| 因子 | 符号 | 取值口径 | 计算说明 |
| --- | --- | --- | --- |
| 相关度 | R(c) | 0–1 | 槽位命中率：材料、刀具/工序、指标三项各占 1/3，命中记 1，未命中记 0；指标允许多命中取平均 |
| 权威度 | A(c) | 0.6–0.95 | 直接取 5.1.1 节的 A_src；S7 专家访谈不得高于 0.60 |
| 时效性 | T(c) | 0.5–1.0 | 有效期内记 1.0；过期 ≤12 个月记 0.8；过期 12–24 个月记 0.6；过期 >24 个月记 0.5 |

入选项与截断规则：Score(c) ≥ 0.65 的片段进入依据候选池，按分值降序排列，取前 5 条；前 5 条中若 A 级条目为 0 条，则整个候选池作废，转入 5.3.4 节无命中处置。同一 kbId 的多个切片只保留分值最高的一个。

### 5.3.3 引用格式

正文引用一律采用方括号编号，不写链接、不写页码长串：

| 引用对象 | 格式 | 示例 |
| --- | --- | --- |
| 知识条目 | `[KB-<领域>-<4位>]` | [KB-CNC-0042]、[KB-ALU-0011] |
| 刀具 | `[T<序号>]` | [T3] |
| 材料 | `[M<序号>]` | [M1] |
| 工序 | `[OP<序号>]` | [OP2] |
| 工艺卡 | `[PC-YYYYMMDD-NNNN]` | [PC-20261109-0007] |
| 试切记录 | `[TR-YYYYMMDD-NNNN]` | [TR-20261105-0012] |
| 检索片段 | `[CHUNK-<检索号>-<序号>]` | [CHUNK-0007-03] |

"来源"段合计不超过 40 字（见 4.1 节），因此只列 kbId 与代号，不展开来源全称；展开信息由前端悬停呈现，写入 JSON 的 evidence 字段。

### 5.3.4 无命中兜底话术

无命中分为三种情形，处置不同，禁止用"一般经验上""通常会"一类措辞过渡。

| 情形 | 判定 | 话术与动作 |
| --- | --- | --- |
| 完全无命中 | 候选池为空 | "知识库中无 [M<代号>]+[T<代号>]+[OP<代号>] 的可用条目，按 NO_EVIDENCE 拒答。可执行动作：改用已覆盖的刀具代号重试，或提交工艺工程师复核。" |
| 仅 C 级命中 | 候选池非空但 A 级为 0 | "仅检索到专家访谈类条目，不足以支撑参数结论" + 输出定性倾向 + 置信度置 LOW + 建议试切 |
| 条目冲突 | 两条 A 级条目同槽位数值不同 | 并列双方数值与编号，置信度置 LOW，转 5.4 节冲突消解 |

### 5.3.5 提示词正文

```text
你是智刃工艺（ZR-CUT）的检索片段重排与引用器，资产编号 ZRCNC-RAG-RNK-001。

职责：对 kb_search 返回的片段做三因子打分、截断、引用编号装配与无命中判定。你不生成参数，不改写片段中的数值。

输入变量：
检索片段集：{{chunks_json}}（每项含 kbId、title、sourceType、sourceRef、scope、metrics、confidence、validUntil、score_raw）
当前日期：{{today}}
目标指标：{{target_metrics}}
会话已用编号：{{used_ids}}

步骤一，逐片段计算相关度 R。材料槽位一致记 1，否则 0；刀具或工序一致记 1，否则 0；指标命中数除以目标指标数。R 为三项平均值。槽位不一致但 materialCode 或 toolCode 为空的片段，按 0.5 计并在 detail 标注"适用范围未声明"。

步骤二，取权威度 A。sourceType 为 S1/S2/S5/S6 取 0.95，S3 取 0.90，S4 取 0.80，S7 取 0.60。条目 confidence 为 C 时 A 再乘 0.8。

步骤三，取时效性 T。依据 validUntil 与当前日期比较：未过期 1.0，过期至 12 个月 0.8，12 至 24 个月 0.6，超 24 个月 0.5。

步骤四，计算 Score = 0.50R + 0.35A + 0.15T，保留三位小数。筛 Score ≥ 0.65，同 kbId 去重保留最高分，降序取前 5 条。

步骤五，A 级硬判据：入选片段中 confidence 为 A 的条目数为 0 时，整池作废，输出 noHit=true 并给出 5.3 节第三种话术，不得降格使用 C 级条目充当主证据。

步骤六，装配引用。正文引用只用 `[KB-<领域>-<4位>]`、`[T<序号>]`、`[M<序号>]`、`[OP<序号>]`、`[CHUNK-<检索号>-<序号>]` 六种形式；一条数值只挂一个主编号，补充编号放入 corroborate 字段。已用编号不得重复挂到不同数值上。

铁律：引用数值必须带 KB 编号。凡是片段中没有出现过的数值，你不得写出；凡是需要计算得出的数值（n、vf、Pc、Ra_th、T），你不得自行计算或估算，一切数值只能来自工具返回，检索层只负责搬运证据。

输出 JSON，字段为 selected（含 kbId、score、R、A、T、quote、metricsUsed）、rejected（kbId、reason）、noHit、fallbackText、citationLine（≤40 字）。输出只允许一个 JSON 代码块。

冲突处理线索：同槽位出现两条 A 级条目且数值不一致时，selected 内两条并列保留，标记 conflict=true，置信度建议置 LOW，交由冲突消解环节处置，你不裁决谁对。
```

### 5.3.6 打分示例

设某一 [KB-CNC-0042] 片段，scope 为 M1+T3+OP2，指标要求 vc 与 Ra，未过期，confidence 为 A，sourceType 为 S2：

- R = (1 + 1 + 1) / 3 = 1.000
- A = 0.90（S2 口径）
- T = 1.0（有效期内）
- Score = 0.50×1.000 + 0.35×0.90 + 0.15×1.0 = 0.500 + 0.315 + 0.150 = 0.965

同一批次的 [KB-TOOL-0021] 专家访谈片段，scope 为 M1+T3 但无 OP 声明，指标命中 1/2，已过期 14 个月：

- R = (1 + 1 + 0.5) / 3 = 0.833
- A = 0.60 × 0.8 = 0.48（confidence 为 C）
- T = 0.6（过期 12–24 个月）
- Score = 0.50×0.833 + 0.35×0.48 + 0.15×0.6 = 0.417 + 0.168 + 0.090 = 0.675

两条均过 0.65 阈值，但排序上 A 级条目在前，且 C 级条目只能进入"风险"补充位，不得为主证据。

## 5.4 知识冲突消解

冲突消解遵循规范 2.5 节优先级：受控工艺卡 > 刀具厂家手册 > 材料手册 > 历史试切 > 通用经验。落到条目层面即 S3 > S1 > S2 > S4 > S7，S5 与 S6 属机台与安全条款，不参与参数优先级排序，一旦与任何参数条目冲突，无条件以 S5/S6 为准。

| 冲突类型 | 判定 | 处置 |
| --- | --- | --- |
| 同槽位同指标、数值差 ≤5% | 一致 | 取优先来源数值，另一条写入 corroborate |
| 数值差 5%–20% | 弱冲突 | 取优先来源，风险段注明"存在差异来源"，置信度降一档 |
| 数值差 >20% | 强冲突 | 双方数值与编号并列，置信度一律置 LOW，转工艺工程师复核 |
| 一方为 C 级 | 等级冲突 | 直接弃用 C 级数值，仅在风险段定性引用 |

无论哪一档，均不得对大模型自行取中位数、加权平均或"折中"给出一个两侧都没有出现过的数值。冲突记录写入知识候选池，作为 5.5 节的复核输入。

## 5.5 知识采集与复核流程

| 环节 | 责任方 | 动作 | 产出 |
| --- | --- | --- | --- |
| 采集 | admin | 按 S1–S7 录入，填写 sourceRef 原始页码或编号 | 草稿条目 |
| 抽取 | process_engineer | 把指标拆为 metrics 数组，逐项写单位 | 结构化条目 |
| 双人复核 | process_engineer + teacher | 两人独立核对数值与适用范围，任一人反对即退回 | 复核签字记录 |
| 签发 | admin | 赋 kbId、confidence，写 validUntil（签发日 +24 个月） | 正式条目 |
| 过期巡检 | admin | 每月扫描 validUntil，过期条目按 5.3.2 节 T 因子降权 | 降权清单 |
| 冲突回流 | process_engineer | 5.4 节强冲突在 5 个工作日内处置 | 修订版条目 |
| 退役 | admin | 被新条目替代时写 supersedes，保留只读副本 | 归档记录 |

复核要求：双人复核的两个角色不得同为一人；S6 安全规程条目必须由 teacher 主复核；S3 受控工艺卡条目须附 PC 编号才可签发；任何条目在 metrics 中缺单位时不允许签发为 A 级。

过期条目不删除，只降权与标记，避免历史试切记录失去可回溯的引用锚点。过期超过 24 个月且无 supersedes 关系的条目，转入只读归档库，检索时按 5.3.2 节 T=0.5 参与打分，几乎必然被 0.65 阈值截断。
